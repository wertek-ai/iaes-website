Common Envelope

Every IAES event shares a common envelope that provides traceability, deduplication, and interoperability across all producers and consumers.

{ "spec_version": "1.3", "event_type": "asset.health", "event_id": "a9e3c4b2-9d3a-4a12-b1f3-2e44a1caa8a1", "correlation_id": "3b2f9d8c-1c33-4a8a-9b77-54d11b2efc12", "source_event_id": "f4ce4f8c-26fd-4f15-8b2f-2c9425ad1110", "batch_id": "batch-2026-03-08-001", "timestamp": "2026-03-08T14:30:00Z", "source": "wertek.ai.diagnosis", "content_hash": "8a3f9c2e1b4d7e6f", "asset": { "asset_id": "MOTOR-001", "asset_name": "Pump Motor P-101", "plant": "Pesqueria", "area": "Turbines" }, "data": { "health_index": 0.16, "anomaly_score": 0.92, "severity": "critical", "failure_mode": "bearing_inner_race", "rul_days": 5, "recommended_action": "Replace bearing immediately", "iso_13374_status": "unacceptable" } }

Envelope fields

  • spec_version — IAES version (currently "1.3")
  • event_type — Canonical event name
  • event_id — Unique event identifier (UUID)
  • correlation_id — Links related events in a flow
  • source_event_id — Traces causal origin
  • batch_id — Groups events from a single batch (v1.1)
  • timestamp — ISO 8601, when the event occurred
  • source — Dot-notation producer identity
  • content_hash — SHA-256 prefix for deduplication
  • asset — Neutral asset identity block
  • data — Event-type-specific payload

7 Event Types

IAES v1.3 covers the full lifecycle from physical observation to maintenance closure and inventory impact.

asset.measurement v1.0

Physical observation

Raw or normalized sensor readings from industrial assets. Vibration, temperature, current, pressure, flow, speed.

asset.health v1.0

Diagnostic assessment

AI or expert interpretation of asset condition. Health score, fault classification, remaining useful life, and recommended action.

maintenance.work_order_intent v1.0

Operational intent

Declares the intent to create a work order. The consumer decides whether and how to act — IAES doesn't prescribe.

maintenance.completion v1.1

Work order closure

Acknowledges work order completion with outcome details, duration, checklist status, and failure confirmation.

asset.hierarchy v1.1

Hierarchy structure

Synchronizes the asset tree — organizations, plants, areas, and equipment — across systems.

sensor.registration v1.1

Sensor lifecycle

Tracks sensor discovery, registration, calibration, and decommissioning across the asset fleet.

maintenance.spare_part_usage v1.1

Parts consumption

Records spare parts consumed during maintenance. Linked to work orders for cost tracking and inventory planning.

Incident Lifecycle Example

A complete incident from detection to resolution. Four IAES events tell the full story — no human intervention needed to close the alert.

08:12
asset.health · onset
Power factor drops to 0.91. Rule engine detects violation. New correlation_id is generated. First alert created.
08:45
asset.health · escalation
Power factor drops further to 0.84. Severity escalated from medium to high. Same correlation_id. No duplicate alert — existing alert updated.
10:03
maintenance.work_order_intent
Consumer creates a work order in MaintainX. Linked to the same correlation_id. Technician dispatched to inspect capacitor bank.
14:10
asset.health · recovery
Power factor recovers to 0.97 for 5 consecutive readings. Recovery event emitted with severity: info, condition_trend: improving. Alert auto-resolved.
correlation_id: 3b2f9d8c-1c33-4a8a — all 4 events share the same ID. One incident, one thread, full traceability.

Standards Alignment

IAES doesn't replace existing standards — it speaks their language in event form.

17359

ISO 17359

Condition monitoring guidelines. IAES maps units_qualifier, sampling_rate_hz, and acquisition_duration_s directly from ISO 17359 measurement practice.

13374

ISO 13374

Condition monitoring data processing. IAES iso_13374_status field maps health events to the 6-layer OSA-CBM architecture (DA → DM → SD → HA → PA → AG).

14224

ISO 14224

Equipment reliability data. IAES iso_14224 object carries failure mode, mechanism, and cause codes for maintenance completion events.

How IAES Relates to Other Standards

Standard Scope Relationship to IAES
ISO 55000 Asset management system IAES events feed ISO 55000 decision processes — the standard says what to manage, IAES carries the signals.
AAS (I4.0) Digital twin shell AAS describes asset structure. IAES describes asset events. They are complementary — events can flow into AAS submodels.
CCOM / IDO Equipment data ontology CCOM defines equipment taxonomy. IAES defines what happens to that equipment. IAES events can reference CCOM class IDs.
OPC UA Machine-to-machine protocol OPC UA moves raw data from PLCs. IAES carries interpreted events above that layer. An OPC UA subscriber can produce IAES events.
ISA-95 Enterprise-control integration ISA-95 defines levels (L0–L4). IAES events flow across those levels — from shop-floor intelligence to enterprise systems.

IAES fills a specific gap: a minimal, vendor-neutral event vocabulary for industrial assets. Existing standards define structure, taxonomy, protocols, and management frameworks. IAES defines the events — what happened, to which asset, with what severity.
