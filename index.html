Industrial Asset
Event Standard

A minimal, vendor-neutral event language for industrial assets. IAES names what happens to equipment — measurements, diagnoses, failures, maintenance actions — so any system can produce, route, and consume asset events without custom integration.

There is no common language for asset events in industry. IAES provides one.

How It Works

PLCs and sensors don't know IAES exists. The intelligence layer — AI models, rule engines, gateways — translates raw signals into standardized events.

1

Edge system detects a condition

A vibration sensor reads 12.4 mm/s on compressor C-12. An energy meter detects power factor dropping to 0.87. A thermal camera sees 94°C on a bearing housing.

2

Intelligence layer generates an IAES event

An AI model, rule engine, or gateway interprets the raw data and emits a standardized IAES event with asset identity, severity, and recommended action.

3

Event is consumed by any system

The same event can simultaneously create a work order in SAP, trigger an alert in Grafana, update a digital twin, and feed an AI model for trending.

Key insight

The PLC doesn't know IAES exists. An AI engine reads raw vibration data and emits an IAES event. A technician opens an app, records a diagnosis, and that's also an IAES event. IAES is the language of the intelligence layer — whether the intelligence is artificial or human.

Incident Lifecycle

A complete incident from detection to resolution. Four IAES events tell the full story — no human intervention needed to close the alert.

08:12
asset.health · onset
Power factor drops to 0.91. Rule engine detects violation. New correlation_id is generated. First alert created.
08:45
asset.health · escalation
Power factor drops further to 0.84. Severity escalated from medium to high. Same correlation_id. No duplicate alert — existing alert updated.
10:03
maintenance.work_order_intent
Consumer creates a work order in MaintainX. Linked to the same correlation_id. Technician dispatched to inspect capacitor bank.
14:10
asset.health · recovery
Power factor recovers to 0.97 for 5 consecutive readings. Recovery event emitted with severity: info, condition_trend: improving. Alert auto-resolved.
correlation_id: 3b2f9d8c-1c33-4a8a — all 4 events share the same ID. One incident, one thread, full traceability.

Philosophy

V

Vendor Neutral

No vendor lock-in. Any system can produce or consume IAES events without proprietary dependencies.

E

Event-Oriented

Events are first-class citizens. Each event is self-contained, traceable, and independently meaningful.

I

Intent, Not Command

IAES declares what should happen, not how. Consumers decide implementation — preserving autonomy and flexibility.

O

Open Standard

Licensed under CC BY 4.0. Free to use, implement, extend, and distribute. Open development on GitHub.

B

Backward Compatible

New versions add optional fields. Existing producers and consumers continue working without changes.

Open Source

IAES is developed in the open. The specification, JSON schemas, examples, and reference implementations are all available on GitHub. Contributions, issues, and discussions are welcome.
