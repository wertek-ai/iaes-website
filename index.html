How It Works

PLCs and sensors don't know IAES exists. The intelligence layer — AI models, rule engines, gateways — translates raw signals into standardized events.

1

Edge system detects a condition

A vibration sensor reads 12.4 mm/s on compressor C-12. An energy meter detects power factor dropping to 0.87. A thermal camera sees 94°C on a bearing housing.

2

Intelligence layer generates an IAES event

An AI model, rule engine, or gateway interprets the raw data and emits a standardized IAES event with asset identity, severity, and recommended action.

3

Event is consumed by any system

The same event can simultaneously create a work order in SAP, trigger an alert in Grafana, update a digital twin, and feed an AI model for trending.

Key insight

The PLC doesn't know IAES exists. An AI engine reads raw vibration data and emits an IAES event. A technician opens an app, records a diagnosis, and that's also an IAES event. IAES is the language of the intelligence layer — whether the intelligence is artificial or human.

An Event Language for Industrial Assets

IAES is more than an integration format. It is an event ontology — a common vocabulary that names everything that happens to an industrial asset.

Condition Monitoring

vibration.anomaly temperature.overheat pressure.out_of_range acoustic.ultrasound.leak current.signature.fault

Energy & Power Quality

energy.power_factor.low energy.voltage.sag energy.thd.exceeded energy.demand.peak energy.consumption.anomaly

Maintenance & Lifecycle

asset.failure.predicted maintenance.work_order.created maintenance.completed asset.inspected spare_part.consumed
Every event name follows the same pattern: domain.subject.condition. A common vocabulary that any system can produce and any system can consume.

What IAES Is

IAES is

  • An event language — it names what happens to assets
  • A JSON schema — minimal, self-describing, machine-readable
  • Transport-agnostic — works over MQTT, REST, OPC UA, Kafka, files
  • Domain-spanning — vibration, energy, maintenance, diagnostics, telemetry
  • Event-driven — each event is independent, traceable, and meaningful
  • Open — CC BY 4.0, no vendor lock-in, free to implement

IAES is not

  • Not a protocol — IAES does not define how bytes move on a wire
  • Not a historian — IAES does not store or query time-series data
  • Not a CMMS — IAES does not manage work orders or schedules
  • Not a digital twin framework — IAES does not model asset structure
  • Not a data model — IAES describes events in motion, not data at rest
  • Not limited to manufacturing — works in energy, O&G, mining, utilities, buildings
IAES is simply an event language for industrial assets.

7 Event Types

IAES v1.2 covers the full lifecycle from physical observation to maintenance closure and inventory impact.

asset.measurement v1.0

Physical observation

Raw or normalized sensor readings from industrial assets. Vibration, temperature, current, pressure, flow, speed.

asset.health v1.0

Diagnostic assessment

AI or expert interpretation of asset condition. Health score, fault classification, remaining useful life, and recommended action.

maintenance.work_order_intent v1.0

Operational intent

Declares the intent to create a work order. The consumer decides whether and how to act — IAES doesn't prescribe.

maintenance.completion v1.1

Work order closure

Acknowledges work order completion with outcome details, duration, checklist status, and failure confirmation.

asset.hierarchy v1.1

Hierarchy structure

Synchronizes the asset tree — organizations, plants, areas, and equipment — across systems.

sensor.registration v1.1

Sensor lifecycle

Tracks sensor discovery, registration, calibration, and decommissioning across the asset fleet.

maintenance.spare_part_usage v1.1

Parts consumption

Records spare parts consumed during maintenance. Linked to work orders for cost tracking and inventory planning.

Common Envelope

Every IAES event shares a common envelope that provides traceability, deduplication, and interoperability across all producers and consumers.

{ "spec_version": "1.2", "event_type": "asset.health", "event_id": "a9e3c4b2-9d3a-4a12-b1f3-2e44a1caa8a1", "correlation_id": "3b2f9d8c-1c33-4a8a-9b77-54d11b2efc12", "source_event_id": "f4ce4f8c-26fd-4f15-8b2f-2c9425ad1110", "batch_id": "batch-2026-03-08-001", "timestamp": "2026-03-08T14:30:00Z", "source": "wertek.ai.diagnosis", "content_hash": "8a3f9c2e1b4d7e6f", "asset": { "asset_id": "MOTOR-001", "asset_name": "Pump Motor P-101", "plant": "Pesqueria", "area": "Turbines" }, "data": { "health_index": 0.16, "anomaly_score": 0.92, "severity": "critical", "failure_mode": "bearing_inner_race", "rul_days": 5, "recommended_action": "Replace bearing immediately", "iso_13374_status": "unacceptable" } }

Envelope fields

  • spec_version — IAES version (currently "1.2")
  • event_type — Canonical event name
  • event_id — Unique event identifier (UUID)
  • correlation_id — Links related events in a flow
  • source_event_id — Traces causal origin
  • batch_id — Groups events from a single batch (v1.1)
  • timestamp — ISO 8601, when the event occurred
  • source — Dot-notation producer identity
  • content_hash — SHA-256 prefix for deduplication
  • asset — Neutral asset identity block
  • data — Event-type-specific payload

Install

IAES ships SDKs for Python, TypeScript, and Node-RED. Zero required dependencies. Install and start emitting events in minutes.

Python

pip install iaes
from iaes import MeasurementEvent, Severity event = MeasurementEvent( asset_id="MOTOR-001", measurement_type="vibration_velocity", value=4.2, unit="mm/s", source="acme.sensors", ) wire = event.to_dict()

Standards Alignment

IAES doesn't replace existing standards — it speaks their language in event form.

17359

ISO 17359

Condition monitoring guidelines. IAES maps units_qualifier, sampling_rate_hz, and acquisition_duration_s directly from ISO 17359 measurement practice.

13374

ISO 13374

Condition monitoring data processing. IAES iso_13374_status field maps health events to the 6-layer OSA-CBM architecture (DA → DM → SD → HA → PA → AG).

14224

ISO 14224

Equipment reliability data. IAES iso_14224 object carries failure mode, mechanism, and cause codes for maintenance completion events.

How IAES Relates to Other Standards

Standard Scope Relationship to IAES
ISO 55000 Asset management system IAES events feed ISO 55000 decision processes — the standard says what to manage, IAES carries the signals.
AAS (I4.0) Digital twin shell AAS describes asset structure. IAES describes asset events. They are complementary — events can flow into AAS submodels.
CCOM / IDO Equipment data ontology CCOM defines equipment taxonomy. IAES defines what happens to that equipment. IAES events can reference CCOM class IDs.
OPC UA Machine-to-machine protocol OPC UA moves raw data from PLCs. IAES carries interpreted events above that layer. An OPC UA subscriber can produce IAES events.
ISA-95 Enterprise-control integration ISA-95 defines levels (L0–L4). IAES events flow across those levels — from shop-floor intelligence to enterprise systems.

IAES fills a specific gap: a minimal, vendor-neutral event vocabulary for industrial assets. Existing standards define structure, taxonomy, protocols, and management frameworks. IAES defines the events — what happened, to which asset, with what severity.

Philosophy

V

Vendor Neutral

No vendor lock-in. Any system can produce or consume IAES events without proprietary dependencies.

E

Event-Oriented

Events are first-class citizens. Each event is self-contained, traceable, and independently meaningful.

I

Intent, Not Command

IAES declares what should happen, not how. Consumers decide implementation — preserving autonomy and flexibility.

O

Open Standard

Licensed under CC BY 4.0. Free to use, implement, extend, and distribute. Open development on GitHub.

B

Backward Compatible

New versions add optional fields. Existing producers and consumers continue working without changes.

Open Source

IAES is developed in the open. The specification, JSON schemas, examples, and reference implementations are all available on GitHub. Contributions, issues, and discussions are welcome.
