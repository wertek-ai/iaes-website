Industrial systems don't speak the same language

Maintenance data flows through dozens of incompatible systems. Each uses its own model, schema, API, and semantics — making it hard to turn observations into operational action.

Typical data sources

  • Vibration, temperature, and pressure sensors
  • Video and acoustic diagnostic systems
  • SCADA, PLC, and historian infrastructure
  • Inspection apps and technician inputs
  • AI models, rule engines, and expert analysis

Typical enterprise destinations

  • CMMS and EAM platforms (SAP, Odoo, MaintainX, Fracttal)
  • Historians and industrial data hubs (PI, AVEVA)
  • Dashboards and BI tools (Grafana, Power BI)
  • Digital twin and reliability applications
  • Maintenance planning and scheduling systems

Why IAES exists

Industrial systems integrate through custom mappings.

Sensor vendors, AI diagnostics, CMMS systems, and historians all use incompatible schemas. Every new connection requires a bespoke adapter, and every adapter is a maintenance burden.

IAES exists to provide a neutral event model that allows these systems to interoperate — without knowing anything about each other's implementation.

IAES introduces a neutral event layer

Instead of building custom integrations between every system, producers emit IAES events and consumers map them to their native format. One standard, many systems.

Seven event types

IAES v1.2 covers the full lifecycle from physical observation to maintenance closure and inventory impact.

asset.measurement

Physical observation

Raw or normalized sensor readings from industrial assets. Vibration, temperature, current, pressure, flow, speed.

measurement_type value unit sensor_id location units_qualifier 1.2 sampling_rate_hz 1.2
asset.health

Diagnostic assessment

AI or expert interpretation of asset condition. Health score, fault classification, RUL, and recommended action.

health_index anomaly_score severity failure_mode rul_days recommended_action iso_13374_status 1.2 iso_14224 1.2
maintenance.work_order_intent

Operational intent

Declares the intent to create a work order. The consumer decides whether and how to act — IAES doesn't prescribe.

title description priority recommended_due_days triggered_by
maintenance.completion

Work order closure

Acknowledges work order completion with outcome details, duration, checklist status, and failure confirmation.

status work_order_id actual_duration_seconds failure_confirmed spare_parts_count iso_14224 1.2
asset.hierarchy

Hierarchy structure

Synchronizes the asset tree — organizations, plants, areas, and equipment — across systems.

hierarchy_level relationship_type parent_asset_id manufacturer is_active
sensor.registration

Sensor lifecycle

Tracks sensor discovery, registration, calibration, and decommissioning across the asset fleet.

sensor_id registration_status measurement_capabilities firmware_version
maintenance.spare_part_usage

Parts consumption

Records spare parts consumed during maintenance. Linked to work orders for cost tracking and inventory planning.

work_order_id spare_part_id quantity_used unit_cost currency

Common event envelope

Every IAES event shares a common envelope for traceability, deduplication, and interoperability.

{ "spec_version": "1.2", "event_type": "asset.health", "event_id": "a9e3c4b2-9d3a-4a12-b1f3-2e44a1caa8a1", "correlation_id": "3b2f9d8c-1c33-4a8a-9b77-54d11b2efc12", "source_event_id": "f4ce4f8c-26fd-4f15-8b2f-2c9425ad1110", "timestamp": "2026-03-06T17:50:17Z", "source": "wertek.ai.diagnosis", "content_hash": "8a3f9c2e1b4d7e6f", "asset": { "asset_id": "MOTOR-001", "asset_name": "Pump Motor P-101", "plant": "Pesqueria", "area": "Turbines" }, "data": { "health_index": 0.16, "anomaly_score": 0.92, "severity": "critical", "failure_mode": "bearing_inner_race", "rul_days": 5, "recommended_action": "Replace bearing immediately" } }

Envelope fields

  • spec_version — IAES version (currently "1.2")
  • event_type — canonical event name
  • event_id — unique event identifier (UUID)
  • correlation_id — links related events in a flow
  • source_event_id — traces causal origin
  • batch_id — groups events from a single batch operation (v1.1)
  • timestamp — ISO 8601, when the event occurred
  • source — dot-notation producer identity
  • content_hash — SHA-256 prefix for deduplication
  • asset — neutral asset identity block
  • data — event-type-specific payload

Shared semantics

severity: info | low | medium | high | critical health_index: 0.0 – 1.0 anomaly_score: 0.0 – 1.0 rul_days: integer

ISO standards alignment

IAES v1.2 aligns with four ISO standards for industrial asset management and condition monitoring. All alignment fields are optional — backward compatible with v1.0 and v1.1.

ISO 55000 — Asset Management

IAES embodies AM principles architecturally: value preservation (health_index), alignment (correlation_id traces decisions), assurance (completion events close the feedback loop).

Alignment: Architectural — no new fields needed

ISO 17359 — Condition Monitoring

Measurement recording per §6.3: signal processing method, sampling rate, and acquisition duration disambiguate measurement values.

units_qualifier sampling_rate_hz acquisition_duration_s

ISO 13374 — CM&D Architecture

7-level health status complements IAES severity: severity is action-oriented (what to do), ISO 13374 status is condition-oriented (what the state is).

iso_13374_status unknown → normal → satisfactory → unsatisfactory → unacceptable → imminent_failure → failed

ISO 14224 — Failure Classification

Structured failure coding: mechanism (why it failed physically), cause (root cause category), detection method. Coexists with the simpler failure_mode field.

iso_14224.mechanism_code iso_14224.cause_code iso_14224.detection_method

Install

IAES ships SDKs for Python, TypeScript, and Node-RED. Zero required dependencies. Install and start emitting events in minutes.

● Python

pip install iaes
from iaes import AssetMeasurement event = AssetMeasurement( asset_id="MOTOR-001", measurement_type="vibration_velocity", value=4.2, unit="mm/s", source="acme.sensors", ) wire = event.to_dict() # IAES envelope

PyPI →

● TypeScript

npm install @iaes/sdk
import { AssetMeasurement } from "@iaes/sdk"; const event = new AssetMeasurement({ asset_id: "MOTOR-001", measurement_type: "vibration_velocity", value: 4.2, unit: "mm/s", source: "acme.sensors", }); const wire = event.toJSON();

npm →

● Node-RED

npm install node-red-contrib-iaes

4 visual nodes for industrial flows:

iaes measurement iaes health iaes work order iaes validate

Drag, drop, wire. Sensor MQTT → IAES event → enterprise system.

npm →

Cross-language compatible — Python and TypeScript produce identical content_hash for the same event. Validate with shared JSON schemas.
