JSON Schemas

Machine-readable definitions for the IAES v2.1 envelope and all eight event types. Each schema is served at the URI its $id declares, https://iaes.dev/schema/v2/<event_type>, byte-identical to the specification release. Use these to validate events in your pipeline.

Common Envelope

Base envelope shared by every IAES 2.x event. Required: spec_version (any 2.x), event_type, event_id, correlation_id, timestamp, source, asset, data. Optional: dataschema, source_event_id, batch_id, content_hash.

/schema/v2/envelope

asset.measurement

Physical sensor reading from an industrial asset. Required fields: measurement_type, value, unit.

/schema/v2/asset.measurement

asset.health

AI diagnosis, rule engine alert, or human expert health assessment. Required fields: health_index, severity.

/schema/v2/asset.health

asset.state

An asset goes up or down: planned or unplanned, why, and what it was doing while up. Required field: state; down_kind when state is down. content_hash is forbidden. New in v2.1.

/schema/v2/asset.state

maintenance.work_order_intent

Declares the intent to create a maintenance work order; the consumer decides whether and how to act. Required fields: title, priority.

/schema/v2/maintenance.work_order_intent

maintenance.completion

Work order completion acknowledgment with outcome details. Required fields: status, work_order_id.

/schema/v2/maintenance.completion

asset.hierarchy

Asset hierarchy structure sync — organizations, plants, areas, and equipment. Required fields: hierarchy_level, relationship_type.

/schema/v2/asset.hierarchy

sensor.registration

Sensor discovery, onboarding, and lifecycle events. Required fields: sensor_id, registration_status.

/schema/v2/sensor.registration

maintenance.spare_part_usage

Spare parts consumed during a maintenance activity. Required fields: work_order_id, spare_part_id, quantity_used.

/schema/v2/maintenance.spare_part_usage

Validation Example

Every event schema references the envelope by its canonical URI, so a validator needs the envelope registered under that URI. With Python’s jsonschema:

pip install jsonschema referencing
curl -sO https://iaes.dev/schema/v2/envelope
curl -sO https://iaes.dev/schema/v2/asset.state
curl -sO https://iaes.dev/examples/asset-state.json

python -c "
import json
from jsonschema import Draft202012Validator
from referencing import Registry, Resource
envelope = json.load(open('envelope'))
schema   = json.load(open('asset.state'))
registry = Registry().with_resource(envelope['\$id'], Resource.from_contents(envelope))
for event in json.load(open('asset-state.json')):
    Draft202012Validator(schema, registry=registry).validate(event)
print('Valid IAES events')
"

Earlier releases stay resolvable: the 1.x schemas are served under /schema/v1/, and the files in this directory (/schemas/*.schema.json) are the frozen 1.4 copies kept so links made before 1.4 keep working. A consumer validates an event against the schemas of the major the event declares.
