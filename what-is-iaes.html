What is IAES?

The Industrial Asset Event Standard — a minimal, vendor-neutral JSON format that gives every industrial system a common language for describing what happens to equipment.

Read the Spec View on GitHub

IAES is a JSON vocabulary that names what happens to industrial equipment.
Measurements, diagnoses, failures, work orders, completions — one format, any transport, any vendor.

// A pump reports a health event. That's it.
{
  "event_type": "asset.health",
  "asset": { "asset_id": "pump-401A" },
  "data":  { "health_index": 0.42, "status": "warning" }
}

The Problem

Industrial facilities run dozens of systems that generate equipment data: SCADA, CMMS, historians, PLCs, vibration analyzers, thermal cameras, energy meters. Each speaks its own language.

When a pump bearing degrades, the vibration sensor logs an alarm in one format, the CMMS creates a work order in another, and the historian records process data in a third. There is no common event language that connects them.

The result: data silos, manual re-entry, delayed responses, and lost context. Integrators spend months building custom bridges that break at every version upgrade.

What IAES Solves

IAES defines a minimal JSON envelope plus seven typed event payloads. Any system can produce and consume IAES events without vendor lock-in or proprietary protocols.

  • One envelope, seven event types — measurements, health changes, work orders, completions, hierarchy, sensor registration, spare parts
  • Vendor-neutral — works with any SCADA, CMMS, historian, or custom system
  • ISO-aligned — optional fields map to ISO 17359, 13374, 14224, and 55000
  • Human-readable JSON — no binary encoding, no schema compilation, no code generation required
  • Transport-agnostic — send via MQTT, HTTP, Kafka, files, or any message bus

How IAES Compares

IAES does not replace existing standards. It occupies a different layer.

Standard Layer Defines Format Asset Events?
OPC UA Communication How machines talk to each other Binary / XML No
MQTT Transport How messages are delivered (pub/sub) Any (opaque bytes) No
Sparkplug B Telemetry model How devices report metrics over MQTT Protobuf Metrics only
AAS Digital twin How to model an asset digitally JSON / XML / RDF No
IAES Event semantics What happened to an asset, why, and what to do JSON Yes

OPC UA moves bytes. MQTT delivers messages. Sparkplug B structures telemetry. AAS models digital twins. IAES names what happened to the asset — and that layer didn’t exist before.

How It Works

Every IAES event is a JSON object with a standard envelope wrapping a typed payload. The envelope identifies what happened, where, and when — the payload carries the domain-specific data.

{
  "event_type":     "asset.health",
  "spec_version":   "1.3",
  "event_id":       "evt-a1b2c3d4",
  "timestamp":      "2026-03-14T08:30:00Z",
  "source_system":  "vibration-monitor",
  "asset_id":       "pump-401A",
  "site_id":        "plant-monterrey",
  "payload": {
    "health_index":     0.42,
    "status":           "warning",
    "condition_trend":  "worsening",
    "diagnosis":        "Bearing inner race defect detected",
    "confidence":       0.89
  }
}

The envelope fields (event_type, asset_id, timestamp) are always present. The payload structure varies by event type.

7 Event Types

Each event type has a JSON Schema, example payloads, and clear field definitions.

asset.measurement

Raw sensor readings — vibration, temperature, pressure, current. Includes units, sampling rate, and acquisition parameters.

asset.health

Computed health status for an asset — health index (0–1), status level, diagnosis text, confidence, and condition trend.

maintenance.work_order_intent

A request to create a work order — priority, description, recommended action. Bridges monitoring to CMMS.

maintenance.completion

Work completed on an asset — what was done, duration, technician, parts used. Closes the maintenance loop.

asset.hierarchy

Organizational structure — site, area, line, asset relationships. Defines where equipment lives.

sensor.registration

A new sensor or gateway coming online — type, location, communication protocol, linked asset.

maintenance.spare_part_usage

Parts consumed during maintenance — part number, quantity, cost, linked work order.

ISO Alignment

IAES events carry optional fields that map directly to established industrial standards.

ISO 17359

Condition monitoring guidance. IAES maps units_qualifier, sampling_rate_hz, and acquisition_duration_s to measurement parameters.

ISO 13374

Machine condition monitoring data processing. The iso_13374_status field maps health events to the 6-layer MIMOSA/OSA-CBM architecture.

ISO 14224

Reliability and maintenance data for equipment. The iso_14224 object captures equipment class, failure mechanism, and failure cause codes.

ISO 55000

Asset management systems. IAES events provide the data foundation for lifecycle visibility, risk assessment, and evidence-based decision making.

Who Uses IAES

System Integrators

Connect SCADA, historians, and CMMS platforms with a standard event format instead of building custom point-to-point bridges for every combination.

Maintenance Teams

Standardize event data across vibration, thermal, and electrical monitoring systems. One format for all condition data feeding into work order decisions.

Platform Vendors

Build interoperable tools that consume events from any IAES-compliant source. Reduce integration cost and expand your addressable market.

Why It Matters

Industrial telemetry generates millions of data points. Most of it is noise. Events are the signal.

1

Telemetry is noisy

A single vibration sensor generates 10,000+ readings per second. No human or system can act on raw data at that volume. You need interpretation.

2

Events summarize state

An IAES event says: “Pump 401A bearing is degrading, health index 0.42, condition worsening.” One JSON object replaces millions of raw samples.

3

Events drive workflows

That same event can create a work order in SAP, trigger an alert in Grafana, update a digital twin, and feed an AI model — all without custom integration per system.
